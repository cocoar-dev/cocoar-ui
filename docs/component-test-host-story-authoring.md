# Component Test Host — Story Authoring Guide

This document explains how to write a `CtStory` today:

- how story discovery works
- how query parameter parsing works
- how to override parsing for individual inputs
- how to provide custom parsers

This is intentionally practical and matches the current implementation.

---

## Mental Model

- A **story** is an Angular component that renders a scenario in isolation (often a wrapper around the real design-system component).
- The host mounts one story at a time at `/__ct/:id`.
- Inputs are configured via URL query params and applied to the story component using `componentRef.setInput()`.

---

## Where To Put Stories

Within the CT host app, stories typically live under:

- `apps/component-test-host/src/app/ct/stories/**`

A story usually has:

- `my-story.component.ts` (+ html/css)
- `my-story.ct-story.ts` (metadata)

The registry is auto-generated by scanning the configured search roots (see `ct-host.config.json`).

---

## The `CtStory` Type

`CtStory` is defined in `apps/component-test-host/src/app/ct/ct-types.ts`.

A minimal story metadata object looks like:

```ts
import type { CtStory } from '../ct-types';
import type { MyStoryComponent } from './my-story.component';

export const myStory: CtStory<MyStoryComponent> = {
  id: 'my-story-id',
};
```

Notes:

- The `id` becomes the URL segment: `/__ct/my-story-id`.
- The generic type (`CtStory<MyStoryComponent>`) is used by the generator to find the component class.
- IDs are set manually and must be **globally unique** within the repository. The registry generator fails if duplicate IDs are detected.

## How Query Param Parsing Works

### 1) Only allowlisted inputs are read

At runtime, the host reads query params and applies them only for allowlisted inputs defined on the registry entry.

Implementation: `apps/component-test-host/src/app/ct/ct-host.page.ts`.

### 2) Each input has a parser

A parser has type:

```ts
export type CtInputParser = (raw: string) => unknown | CtSkip;
```

If a parser returns `CT_SKIP`, the value is ignored (no input is set).

This is the default behavior for invalid values: we **ignore invalid query parameter values** rather than throwing.

Implementation: `apps/component-test-host/src/app/ct/ct-parsers.ts`.

### 3) Only the first query param value is used

Angular `ParamMap.get(name)` returns the first value.

So this URL:

- `?disabled=true&disabled=false`

will pass only the first value (`true`) to the parser.

---

## Parser Helpers (Built In)

These helpers exist in `apps/component-test-host/src/app/ct/ct-parsers.ts`.

### `ctParseBoolean(raw)`

- Accepts common “truthy” values: `true`, `1`, `yes`, `on`
- Special case: empty string means `true`
  - so `?disabled` will be treated as `disabled=true`

### `ctParseNumber(raw)`

- `''` (empty) → `CT_SKIP`
- non-finite / NaN → `CT_SKIP`
- otherwise returns a `number`

### `ctParseString(raw)`

- returns the string as-is

### `ctParseEnum(['a','b'])`

- if `raw` is in the allowlist → returns `raw`
- otherwise → `CT_SKIP`

## Auto-Inferred Inputs (Most Common Case)

The registry generator auto-infers an allowlist of inputs by scanning the story component class for signal inputs declared using Angular’s `input()` API.

Example story component:

```ts
import { Component, input } from '@angular/core';

@Component({
  standalone: true,
  template: `...`,
})
export class MyStoryComponent {
  disabled = input(false);
  label = input<string>('Hello');
  size = input<'sm' | 'md' | 'lg'>('md');
  count = input<number>(0);
}
```

What this means:

- `disabled` → boolean parser
- `label` → string parser
- `size` → enum parser (for small string-literal unions)
- `count` → number parser

The generator currently:

- detects `input(...)` and `input.required(...)`
- supports: `boolean`, `number`, `string`, and small string-literal unions (max 50) for enums
- falls back to string parsing for unknown/complex types

## Overriding Parsing For A Single Input

You can override inferred parsers by adding an exported story in a `*.ct-story.ts` file.

Important constraint:

- overrides are only applied when the story metadata is:
  - **exported**, and
  - defined in a `*.ct-story.ts` file

Reason: the generated registry only imports metadata from `*.ct-story.ts` to avoid eager-loading story chunks.

### Example: override one input

```ts
import { CT_SKIP, ctParseEnum, ctParseString } from '../../ct-parsers';
import type { CtStory } from '../../ct-types';
import type { MyStoryComponent } from './my-story.component';

export const myStory: CtStory<MyStoryComponent> = {
  id: 'my-story-id',
  inputs: {
    // override inferred string parsing
    label: (raw) => ctParseString(raw).trim(),

    // replace inferred enum with a stricter allowlist
    size: ctParseEnum(['sm', 'md']),

    // completely disallow an input from query params
    count: false,

    // custom parser that can skip invalid values
    mode: (raw) => (raw === 'auto' || raw === 'manual' ? raw : CT_SKIP),
  },
};
```

Semantics:

- omitted key → use inferred parser
- `CtInputParser` → override inferred parser
- `false` → remove this input from the allowlist

## Adding Providers (Per Story)

If a story needs providers (overlays, stubs, test doubles), add them on the story metadata (same export constraint as above):

```ts
import type { CtStory } from '../../ct-types';
import type { MyStoryComponent } from './my-story.component';
import { provideNoopAnimations } from '@angular/platform-browser/animations';

export const myStory: CtStory<MyStoryComponent> = {
  id: 'my-story-id',
  providers: [provideNoopAnimations()],
};
```

## Writing Custom Parsers (Guidelines)

A custom parser should:

- accept a single string
- return a value compatible with the story input
- return `CT_SKIP` for invalid input

Examples:

### Comma-separated string list

```ts
import { CT_SKIP } from '../../ct-parsers';

export function parseStringList(raw: string) {
  const normalized = raw.trim();
  if (normalized === '') return CT_SKIP;
  return normalized
    .split(',')
    .map((s) => s.trim())
    .filter(Boolean);
}
```

### Strict JSON parser (careful)

```ts
import { CT_SKIP } from '../../ct-parsers';

export function parseJson(raw: string) {
  try {
    return JSON.parse(raw);
  } catch {
    return CT_SKIP;
  }
}
```

Recommendation: keep parsers small and deterministic. Prefer query params that are easy to read and debug.

## Troubleshooting

### “My overrides are ignored”

Check:

- story metadata is `export const ...`
- file name ends with `*.ct-story.ts`

If the story is declared only in a `*.component.ts`, the generator can discover the `id` but cannot import overrides without eager-loading.

### “My param is not applied”

Common reasons:

- not part of the allowlist (no `input()` field and no override)
- parser returned `CT_SKIP` because the value was invalid
- key name mismatch (query param name must match the input name exactly)
