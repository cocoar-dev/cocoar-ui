# Component Preview Platform

## Summary

We are building a small, dedicated Angular application that can **render exactly one component scenario in isolation** (preview-iframe style) and make it available for:

- **automated UI tests** (Playwright)
- **manual exploration** (developers/designers)
- **future showcase integration** (documentation + live preview in a dedicated tab)

This repo intentionally avoids third-party preview tooling, so this platform is our **controlled, Angular-first alternative**.

---

## Why This Exists

### Problem

We need reliable component-level tests and reproducible demos. Using a full showcase route for testing introduces:

- test flakiness from unrelated page layout and navigation
- selectors polluted by “showcase chrome”
- higher maintenance cost as demo pages evolve

Many preview tools solve this by rendering each scenario in its own deterministic iframe.

### Solution

Create a **minimal preview host** that mounts one scenario at a time via a stable URL contract:

- `/<preview-route>/:id` mounts exactly one scenario
- query parameters configure a small allowlist of inputs
- optional per-scenario providers support overlays, i18n stubs, etc.

This becomes the stable surface for Playwright and a consistent “try it out” UI.

---

## What It Does (Today)

### Core capabilities

- **Isolated rendering**: one scenario per route
- **Lazy loading**: scenarios are loaded by dynamic `import()`
- **URL-driven inputs**: query params → typed parsing → component inputs
- **Provider overrides**: optional per-scenario providers
- **Auto-discovery**: scenario registry is generated by scanning the repo
- **Guardrails**: runtime code cannot import scenario metadata directly (enforced)

### Authoring model

Instead of rendering a design-system component directly, we author **wrapper components** (“scenarios”) that can:

- handle content projection
- include small layouts
- stitch multiple components together
- include overlays or templates

This mirrors the common “template wrapper” approach used by preview tooling, but stays 100% Angular.

---

## What It Enables

### 1) Isolated component testing

Playwright tests become direct and stable:

- Navigate to a deterministic URL
- Assert behavior with minimal DOM noise
- Keep tests focused on one component state

### 2) Manual component exploration

Developers can open a scenario URL and tweak inputs via query params.

### 3) Future: Showcase integration

Long-term, we can integrate isolated previews into the existing showcase app without turning the showcase into the test harness.

Conceptually:

- Showcase keeps docs, examples, API tables, guidelines
- The preview platform provides the **live isolated preview**
- The showcase embeds the preview in a dedicated “Preview” tab (likely an iframe)

This keeps the testing surface stable even when docs UX changes.

---

## Non-Goals (For Now)

To keep the platform maintainable, we are intentionally *not* implementing the full feature set of dedicated preview tools.

Examples of non-goals (for early versions):

- addons ecosystem
- complex UI for “controls” panels (beyond URL params)
- visual regression tooling built-in
- automatic docs generation from TS types (beyond what we already infer)

These can be evaluated later if there is a clear ROI.

## Roadmap (High Level)

### Near-term

- Expand scenario coverage for key components
- Add more Playwright scenarios and helpers
- Make the tooling portable to non-Nx Angular CLI repos

### Mid-term

- Provide a small “scenario explorer” UI (optional)
- Integrate a preview tab into showcase (embed isolated preview)
- Improve type inference and support more Angular input patterns

### Long-term

- Turn this into a reusable internal product (dedicated repo)
- Provide an installer/CLI to bootstrap the preview platform in any Angular project

## Terminology

The platform uses the following terminology:

| Term | Meaning |
|------|---------|
| **Scenario** | A reproducible component state defined with `defineScenario<T>()` |
| **Backstage App** | The Angular host app that renders scenarios in isolation |
| **Registry** | Auto-generated index of all scenarios (`SCENARIO_REGISTRY`) |
| **Route** | `/__scenario/:id` — stable URL for each scenario |

See [Writing Scenarios](writing-scenarios.md) for the full authoring guide and [Scenar System](scenar/README.md) for the technical documentation.
