i18n (Translations)

Translation (i18n) and locale formatting (localization) are related but separate concerns. This page shows how to configure @cocoar/i18n and how it fits together with the localization service.

Examples API Docs

Recommended setup (Transloco)

Use @cocoar/i18n-transloco to connect Cocoar’s i18n abstraction to Transloco. Provide CoarI18n once at app (or route) level.

Custom backend setup

If you have a custom translation system, provide a CoarI18nProvider via COAR_I18N_PROVIDER. Add COAR_I18N_EVENTS (recommended) so template pipes and reactive APIs update when the language changes.

Using translations in templates

Use CoarI18nPipe with optional fallback texts so the UI remains usable even without a translation backend.

Using translations in TypeScript

Pick the API that matches your component style: t() for synchronous reads, t$() for Observables, and tSignal() for Signals.

How it relates to localization

Localization formats numbers/dates; i18n picks text. Format values first and pass them as params into translations. See the Localization page for formatting setup.
