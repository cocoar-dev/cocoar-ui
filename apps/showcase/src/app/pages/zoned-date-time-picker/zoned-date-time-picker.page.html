Zoned DateTime Picker

A strongly-typed datetime picker that returns Temporal.ZonedDateTime with full timezone support. Captures user intent (local time + timezone) and can derive UTC instants.

Store Intent, Derive Math: This picker captures the user's intended local time and timezone. The UTC instant is derived and can be recalculated if DST rules change.
Examples

Basic Usage

A zoned datetime picker that uses the timezone from CoarTimeZoneService. Returns Temporal.ZonedDateTime | null.

Selected: {{ formatZonedDateTime(basicZonedDateTime()) }}
Type: Temporal.ZonedDateTime | null

Different Timezones

ZonedDateTimePicker can work with any IANA timezone. The timezone badge shows where the event "lives".

Same Moment, Different Clocks:

@if (viennaDateTime()) {

Vienna: {{ formatZonedDateTime(viennaDateTime()) }}
→ Instant: {{ formatInstant(viennaDateTime()?.toInstant() ?? null) }}

}

Locked Timezone

Use timeZoneLocked to protect the timezone from accidental changes. Users can see the timezone but cannot modify it.

Selected: {{ formatZonedDateTime(lockedTzDateTime()) }}

Instant Output

The (instantChange) output emits the derived UTC instant whenever the value changes. Use this for API calls, storage, or sorting.

User Intent: {{ formatZonedDateTime(instantDemoDateTime()) }}
Derived Instant (UTC): {{ formatInstant(lastInstant()) }}

Intent vs Instant

The key insight: store intent, derive math. The ZonedDateTime preserves both what the user meant (local time + timezone) and what moment that represents (instant).

Why This Matters: If you only store the UTC instant, and DST rules change, a 10:00 AM meeting could become 9:00 AM or 11:00 AM. By storing the local time + timezone, you can always recalculate the correct instant.
