Localization Service

Provides locale-aware formatting rules (numbers and dates). This is intentionally not translation/i18n — it defines formatting like decimal separators and date patterns.

Examples API Docs

Default usage

Components inject the service via COAR_LOCALE_SERVICE (optional). If you do nothing, the default CoarLocaleService is used.

Set the default locale once

If your app has a known default locale, set it during startup. Components that do not receive an explicit locale input can use this default.

Provide a custom implementation

If you already have a locale/formatting system (user preferences, tenant settings, etc.), provide your own implementation via Angular DI.

Register custom locale IDs

You can register an app-specific locale id to override formatting rules (partially or fully). This is useful for specialized contexts (e.g. financial exports).

How UI components consume it

Both Date Picker and Number Input use the localization service as a fallback for formatting rules. You can always override per component via inputs.
