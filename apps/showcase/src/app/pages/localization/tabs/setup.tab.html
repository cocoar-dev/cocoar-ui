Providers

Add the localization providers to your app config. The Intl API provides complete formatting defaults for any BCP 47 tag — no locale files needed. HTTP sources are optional for business-specific overrides.

Source Priority

Sources are loaded in parallel and deep-merged. Later sources override earlier ones at field level.

  1. Intl Source — Browser Intl API (always first, provides complete defaults)
  2. HTTP Source — Optional JSON overrides for business rules
  3. Custom Sources — Extensible via multi-provider (SignalR, WebSocket, etc.)
Graceful degradation: If HTTP fails (404, timeout, invalid JSON), the system falls back to Intl defaults and logs a warning.

File Fallback Strategy

HTTP loaders merge base + regional files automatically.

Regional files are optional and only need keys that differ from the base. A missing regional file is silently ignored — the base file serves all variants.

Loading Behavior

Translation Loading (i18n)

  1. HTTP Loader (default) — Loads from /i18n/{lang}.json
  2. Custom Loaders — Implement CoarTranslationLoader for SignalR, static, IndexedDB, etc.

Translations are cached after first load. Switching back to a previous language is instant.

Locale Data Structure (L10n)

Optional JSON files that override Intl defaults with business-specific formatting rules.

Custom HTTP Source

Configure custom URL patterns and headers for both L10n and i18n sources.
