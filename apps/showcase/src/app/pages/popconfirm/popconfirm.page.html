Popconfirm

Accessibility & Best Practices

Guidelines for effective popconfirm usage.

Keyboard Navigation

Popconfirm is fully accessible with keyboard and screen reader support.

  • Enter / Space - Open popconfirm on trigger
  • Tab - Navigate between confirm and cancel buttons
  • Enter - Activate focused button
  • Escape - Close popconfirm (same as cancel)

When opened, focus moves to the popconfirm. When closed, focus returns to the trigger element.

Best Practices

Do's and don'ts for effective confirmation dialogs.

Do
  • Use for destructive actions (delete, remove, discard)
  • Write clear, action-specific messages
  • Use confirmVariant="danger" for destructive actions
  • Keep messages concise and scannable
Don't
  • Use for every action - reserve for important confirmations
  • Write vague messages like "Are you sure?"
  • Nest popconfirms within other overlays
  • Use for complex forms - use a modal instead
Popconfirm API

Directive Inputs

Name Type Default Description
coarPopconfirm string - Message text displayed in the popconfirm
popconfirmTitle string - Optional title above the message
placement 'top' | 'bottom' | 'left' | 'right' 'top' Preferred placement relative to trigger
confirmText string 'Confirm' Text for the confirm button
cancelText string 'Cancel' Text for the cancel button
confirmVariant 'primary' | 'danger' 'primary' Visual variant of confirm button
popconfirmDisabled boolean false Disable the popconfirm (action proceeds directly)

Directive Outputs

Name Type Description
confirmed EventEmitter<void> Emits when user clicks the confirm button
cancelled EventEmitter<void> Emits when user clicks cancel or presses Escape
